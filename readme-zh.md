# ReAct Wiki 1.5

**一个为 SillyTavern 提供维基百科辅助的角色扮演代理小程序。**

该项目旨在探索在生成虚构续写之前检索外部参考资料，是否能为角色的动机、人际冲突和世界观构建带来有益的多样性。它的贡献在于应用程序和提示词设计的实验，而非一种新的推理架构或经过科学验证的人类行为模型。

**本文档记录的版本：** 原始提供的 `react_proxy.py`、预设、中文 `readme.txt` 和启动器。这份中文文档包含完整的源码审查和离线特性分析。它不描述拟议中的重构实现。本次审查未执行实时提供商、实时维基百科、Windows 启动器或 SillyTavern 的端到端测试。

> **运行前须知：** 脚本的直接启动会绑定到所有网络接口，且没有应用程序身份验证。请使用下文提供的仅限本地环回（loopback-only）命令。不同对话之间持久化的理论计数并不能可靠地隔离，而且“三次法则”仅是一个提示词指令，并非后端的硬性限制。请在可随时丢弃且不含敏感信息的测试场景中使用。

## 第一部分：原理与实际行为

### 创作目的与 ReAct

作者编写了主题描述，并利用 LLM 协助将其整理为九个维度及实现代理。一个场景可以通过不同的解释视角来考量：例如，公会谈判可能涉及制度合法性、信息不对称或亲属义务。作者仍需判断某个视角是否有助于场景塑造。预设中的心理学和社会学语言不应被视为临床诊断或既定的普遍规律。[^original][^preset]

Yao 等人将 ReAct 描述为将推理与动作交织在一起，动作的观察结果会为后续决策提供依据。该代理实现了一个小型的、基于文本的改编：请求模型响应，识别维基百科动作，执行它，追加观察结果，然后再次调用模型。Python 源码证实了该反馈循环。它没有复现论文中的实验、重新训练模型，也没有使用评分后的候选方案来优化提示词。[^react][^loop]

此处实现的外部检索源是维基百科。模型生成的搜索词并不能证明存在一个提供商内部独立的 RAG 数据库。该脚本不包含向量索引、嵌入管道，也没有集成作者个人设置中提到的额外检索服务。九个维度的提示词定义不会被代理重写。持久化存储保存的是声明的理论使用次数，而不是文章文本或动态修订的科学框架。[^tools][^state]

### 九个维度

这些是原始预设中的搜索提示词，不能保证维度的独立性或理论的有效性。[^preset]

| 维度 | 提示词示例 |
| --- | --- |
| 政治权威与法理学 | 暴力垄断；法律多元主义 |
| 社会建构与控制 | 结构人类学；生命政治 |
| 角色心理与认同 | 精神分析、格式塔及与认同相关的框架 |
| 人际互动 | 拟剧论；信息不对称 |
| 理性决策 | 理性选择理论；经济人 |
| 政治立场 | 政治光谱；马蹄铁理论 |
| 艺术、遗产与文化价值 | 艺术社会学；文化资本 |
| 思想传播与本体论 | 模因论；行动者网络理论 |
| 亲属关系与社会联系 | 亲属关系；拟制血亲 |

预设决定了请求中包含哪些维度。该代理不维护九个独立验证的状态对象，也不保证在一个轮次（turn）中会对所有九个维度进行检索。

### 请求期间会发生什么

一个**轮次（turn）**是指来自 SillyTavern 的一次补全请求。一个**迭代（iteration）**是指该请求内的一次上游模型调用。[^loop]

1. 代理复制非空的消息字符串，仅保留 `role` 和 `content`。它扫描其中的 `SESSION_ID` 标记，默认值为 `default`。
2. 它加载理论计数，或者当只剩下最多两条非系统消息时，立即清除它们。如果存在系统消息，它会将计数和耗尽警告追加到第一条系统消息中。
3. 它调用配置好的上游模型。有效负载仅包含配置的 `model`、复制的 `messages`、客户端提供的（或默认的）`temperature` 以及有上限限制的 `max_tokens`。
4. 它在返回的 `reasoning_content` 和 `content` 的拼接文本中搜索第一个动作标记。如果匹配，则触发工具，随后追加一条 assistant 内容消息和一条 user 角色的观察（observation）消息。
5. 如果未识别出动作，它将提取叙述内容及可选的元数据，尝试更新计数，在前面加上 HTML 详情面板，并返回结果。缺失的叙述内容会被替换为警告信息。
6. 默认情况下，该循环最多允许 5 次上游调用。如果每次调用都包含一个动作，那么第 5 个动作仍会被执行，其观察结果不会被另一次调用使用，且代理将返回 `SIMULATION ERROR: Maximum ReAct iterations reached.`。

最后一轮的限制仅仅是一个提示词警告。它并没有在工具分发前被强制执行。无论是上游由于生成长度导致的停止，还是元数据缺失/格式错误，都没有被可靠地视为不成功的最终结果。这些是已知的局限性，而非预期的保障。[^loop][^format]

### 旧版工具与动作语法

```text
::: ACTION_CALL: SEARCH_WIKI | Information asymmetry :::
::: ACTION_CALL: READ_WIKI_PAGE | Information asymmetry :::
```

`SEARCH_WIKI` 使用 MediaWiki 搜索 API 并返回最多三个标题和摘要。`READ_WIKI_PAGE` 请求带有 `exintro=1` 的纯介绍性文本，通过 API 跟随文章标题重定向，并截取前 2000 个 Python 字符串字符。它**不**读取整篇文章。MediaWiki 将 `exintro` 定义为第一章节之前的内容。[^tools][^extracts]

存在一个截断通知的 Bug：文本在 2,000 个字符处被切断，但仅当原始提取内容超过 3,000 个字符时才会添加通知。因此，2,001 到 3,000 个字符的摘要在缩短时没有通知。返回的标签 `FULL TEXT OF` 会产生误导。

预设要求在 `<thinking>` 块内提供动作文本，同时又要求只输出动作。解析器没有强制执行任何一种结构：它在最新合并的模型响应中的任何位置进行搜索，并接受第一个匹配的标记。甚至叙事中引用的标记也可以触发请求。当动作仅出现在 `reasoning_content` 中时，下一条 assistant 消息的 `content` 可能为空。这是一个自定义的文本协议，而不是原生的函数调用（function calling）；上游有效负载没有 `tools` 字段。[^loop]

### 理论计数：它们的意义与非意义

预设要求提供四个元数据字段：`Dominance_Shift`、`Cognitive_Dissonance_Level`、`World_Entropy` 和 `Active_Theories_This_Turn`。前三个是生成的叙述性注释，而不是校准过的测量值。最后一个是使用声明，并不能独立证明其在散文中得到了应用。[^preset]

后端接受 `Active_Theories_This_Turn` 及其两个旧版备用名称。它会尝试 JSON 解析，若失败则回退至宽松的正则匹配。返回的每个名称都会增加其完全匹配的字符串键的值。同一数组中重复的名称可以增加两次；拼写替代写法可能是独立的键；格式错误的元数据可能会引入不相关的字符串作为理论名称。[^state]

计数达到三次会生成切换指令。代码不会拒绝该理论、要求重新搜索，也不会将其从预设中删除。可以在计数为三次时接受声明，并将其增加到四次。因此，原 README 中关于“保证排除”的说法过于绝对。

数据库文件是**进程工作目录**下的 `theory_db_<sanitized-session>.json`。提供的预设中没有包含 `SESSION_ID` 标记。除非通过其他集成添加了该标记，否则请求将使用 `theory_db_default.json`。这并不是可靠的单聊天维度存储。标记也可以从任意消息角色中获取，并且不同的标识符可能被清理为相同的文件名。短历史记录重置发生在上游生成成功之前；损坏的 JSON 会被静默处理为空数据库。[^state]

1.5 版本中**没有持久化的理论哈希、摘录摘要、源快照或独立的校验和验证器**。这些都是建议增加的内容。

### 现有的显示与传输

最终回复包含一个可折叠的 HTML `Cognitive Matrix` 面板，其中汇总了代理事件、来自最后一次模型调用的可选推理文本以及提取的元数据。这是嵌入在 assistant 消息中的补全后输出，而不是实时的弹出窗口。脚本转义了面板插入的文本，但它并没有从后续传入的历史记录中移除该面板。如果客户端原封不动地将该回复发回，面板和推理文本就会变成普通的模型上下文。[^format]

当 `stream=true` 时，服务器首先完成整个循环。然后它在一个 SSE 内容块中发送整个响应，接着是完成块和 `[DONE]`。这是缓冲的 SSE，而不是渐进式的 token 流。JSON/SSE 封套使用固定的标识符和时间戳，不报告 token 使用情况，并且通常在即使上游因 `length` 结束时也报告 `stop` 状态。[^transport]

### 实验边界

源码审查确认存在可执行的反馈循环，但不确认写作质量有所提高。作者与随机理论选择的比较是非正式的。原始 ReAct 论文未评估这一角色扮演实现。[^original][^react]

旧版预设包含与检索无关的成人内容和安全覆盖指令。它们不是 ReAct 的要求。进行专业演示时，请使用独立版本控制、不含显式内容的预设；仅禁用名为 `nsfw` 的块并不会移除其他地方的指令。

## 第二部分：原 1.5 版本用户指南

### 1. 准备文件与 Python 环境

使用一个功能正常的 SillyTavern 安装版，并保持其官方的 `Start.bat` 原样不变。中文说明似乎指代 Python 3.11 或更高版本；但未提供最低版本矩阵或依赖锁文件。离线审查在 Python 3.13.5 下运行，但这并不能证明与所有 Python 或包版本兼容。

直接的第三方导入库包括 `fastapi`、`uvicorn` 和 `httpx`。如果要在 Windows 命令提示符下建立隔离环境：

```bat
cd /d "C:\path\to\SillyTavern\EODHCTSiqsxajs-react-wiki1.5\react-proxy"
python -m venv .venv
call .venv\Scripts\activate.bat
python -m pip install fastapi uvicorn httpx
```

该命令基于实际的导入项；它并非提供的版本锁。请记录安装的版本以便重现。如果已在另一命令下配置了解释器，请始终一致地选择该解释器。

建议的文件排列：

```text
SillyTavern/
  Start.bat                       # 官方 SillyTavern 启动器
  Launch-ReAct.bat                 # 可选的重命名包装器，未以此名称提供
  EODHCTSiqsxajs-react-wiki1.5/
    EODHCTSiqsxajs-react-wiki1.5预设.json
    readme.txt
    react-proxy/
      react_proxy.py
      .venv/
```

**绝不能用提供的 `start.bat` 覆盖 SillyTavern 的 `Start.bat`。** 在常规的 Windows 安装中，这两个名称会冲突，且该包装器末尾的 `call Start.bat` 会再次调用该包装器自身。早前的中文指南使用了一个不同的包装器名称。在此问题修复前，请分别独立启动这些进程。[^launcher]

### 2. 配置实际上游端点

在本地私有的 `react_proxy.py` 副本中，编辑第 27-30 行附近的配置常量：

```python
REAL_LLM_URL = "https://api.deepseek.com/chat/completions"
REAL_LLM_API_KEY = "YOUR_PRIVATE_API_KEY"
REAL_LLM_MODEL = "deepseek-reasoner"
MAX_REACT_ITERATIONS = 5
```

这些是原始端点/模型的默认值；提供的 API key 为空。请确认所选的提供商仍然支持配置的模型。不同的提供商必须返回兼容的响应结构，本次审查未测试它们的行为。URL 是**完整的上游端点**，包含 `/chat/completions`；代码不会自动追加该后缀。

客户端侧的别名 `react-engine` 不会选择真实的模型。`REAL_LLM_MODEL` 会在上游有效负载中覆盖它。同样，许多预设控制参数，包括 `top_p`、`seed` 和 `reasoning_effort`，根本不会被转发。即便转发了某个设置，也不一定在提供商那边有效；请查阅所选模型的文档。[^loop][^deepseek]

原始脚本未实现环境变量和 `.env` 加载。不要假设设置了环境变量就能配置这些常量。永远不要提交配置好的密钥，也不要将它们包含在截图中。

### 3. 在本地环回启动代理

在激活了虚拟环境且工作目录包含 `react_proxy.py` 的情况下，使用：

```bat
python -m uvicorn react_proxy:app --host 127.0.0.1 --port 8001
```

这种方式导入现有的 FastAPI 应用程序，而不是运行文件中的 `__main__` 块。它避免了原始 `python react_proxy.py` 的启动方式（这种方式会明确绑定到 `0.0.0.0`）。这是运行原始代码的另一种调用方式，并非声称其默认绑定已被修复。[^transport][^uvicorn]

原始应用程序没有客户端身份验证或速率限制，并允许宽泛的 CORS 访问。本地环回可以减少网络暴露，但不会使该应用程序成为经过身份验证的服务。不要通过公共隧道或端口转发来暴露它。否则，能够访问的客户端将能够使用服务器配置的上游凭据提交生成请求。

在另一个终端窗口中，运行完整的官方 SillyTavern 启动器。提供的包装器仅等待两秒钟；它既不会验证是否就绪，也不会自动激活上述创建的虚拟环境。

### 4. 导入预设并连接

将 `EODHCTSiqsxajs-react-wiki1.5预设.json` 作为聊天补全（Chat Completion）预设导入。检查有效的提示词管理器（Prompt Manager）配置：ReAct 块、相关的维度提示词、续写块和状态追踪器必须被切实包含。保存的 `prompt_order` 配置各不相同，因此提示词在 JSON 中的存在并不能证明它被传输了。[^preset]

使用同机代理的基础 URL：

```text
http://127.0.0.1:8001/v1
```

保持面向客户端的基础 URL 与完整的上游端点不同。预设中保存的通配符地址并非推荐的客户端目标。根据连接需要选择本地广播的 `react-engine` 别名；真正的上游模型仍然由 Python 配置决定。

对 `/v1/models` 的请求只能验证该路由是否有响应；其模型列表是静态的，并不能测试上游凭据、模型可用性、维基百科或生成是否成功。

此版本仅保留纯文本请求。预处理程序假设每个 `content` 值都是字符串。由列表组成的内容部分（Content-part lists）和显式的 null 值可能会引发异常，而不是被标准化处理。

### 5. 设置保守的上下文和输出限制

不要将预设中保存的 2,000,000 token 上下文设置视为实际的后端容量。该代理不执行上下文窗口的计算。它会将有效的数字 `max_tokens` 值限制为最多 8,192，但不会从模型的上下文预算中减去历史记录、参考文本、元数据或提供商特定的推理配额。[^loop]

请为每个累积的观察结果和中间的 assistant 消息保留余量。每次调用的概念性约束为：

```text
序列化输入 token + 提供商相应的生成预留 + 余量 <= 支持的模型上下文容量
```

原始的固定字符减法公式并不是可靠的 token 预算。一段 2,000 字符的摘录不一定等于 2,000 个 token。在此版本中，减少历史记录、输出长度、活动维度或迭代次数是手动妥协的做法。代理无法恢复 SillyTavern 从未发送过的历史记录。

120 秒的上游 HTTPX 超时和 10 秒的维基百科超时是网络操作超时，并非总的轮次截止时间。HTTPX 将连接、读取、写入和池超时分开处理。因此，重复的请求可能会比配置的单次超时时间长得多。[^loop][^tools][^timeouts]

### 6. 运行一次性的冒烟测试

使用一个简短的虚构场景，涉及一两个相关的维度。观察代理控制台中的迭代、实际工具执行、观察结果以及随后的最终回复。最终的详情面板仅作为补充证据，并非实时进度显示。

检查启动工作目录中确切的 JSON 数据库文件。将其值视为模型声明的计数，而非理论应用的证明。在进行实验前备份状态；不要依赖开启新聊天或仅保留短历史记录来提供安全的隔离。原始版本最好仅用于受控的、按顺序进行的实验，直到状态管理得到修复。

工具失败会作为文本返回给模型，模型可能依然会生成故事。因此，仅仅出现故事不能证明检索成功。开启流式传输不会让进度更早显示。

### 7. 故障排除

| 症状 | 相关的局限性或检查项 |
| --- | --- |
| 重复的命令窗口或端口冲突 | 包装器名称与官方的 `Start.bat` 冲突；停止包装器并恢复官方启动器 |
| 导入错误 | 激活指定的环境并检查 `fastapi`、`uvicorn`、`httpx` |
| 静态模型列表有效，但生成失败 | 模型列表不会测试上游凭据或配置的提供商模型 |
| 所有聊天都影响同一个计数文件 | 此预设未提供会话标记；默认存储是共享的 |
| 请求失败后计数消失 | 短历史记录重置发生在上游成功之前；损坏的文件也会被加载为空 |
| 理论使用次数超过三次 | 排除只是模型指令，而不是后端检查 |
| 长时间等待，然后出现一次巨大回复 | 整个循环都被缓冲；同步的维基百科请求也会阻塞事件循环 |
| 最大迭代次数错误 | 未遵循仅限最后一次（Final-only）的警告；代码并未阻止最后一次动作 |
| 部分故事被报告为完成 | 正常的最终路径会将上游的完成原因覆盖为 `stop` |
| 一般性的内部服务器错误 | 异常和上游状态码没有被一致地转换为客户端错误 |
| 当前上下文意外增长 | 最终的 HTML 诊断面板可能会在后续的历史记录中返回；不存在自动的上下文预算 |

### 8. 数据处理与致谢

代理可在本地运行，而推理过程仍在远端。它会将组装好的聊天上下文发送给配置的模型提供商，并将查询/文章标题发送给英文维基百科。最终回复可能包含返回的推理文本；除非故意进行了脱敏处理，否则请将日志和聊天记录视为私人信息。

原始应用程序会持久化保存理论名称的计数，但没有结构化的源修订或摘录哈希的审计追踪。其补全后的控制台/面板事件并不是完整的出处记录。拟议中的状态弹窗和独立的哈希验证器属于未来版本的内容。

记录项目源哈希或提交记录、生效的预设、Python/依赖项版本、SillyTavern 版本、真实提供商模型、实际传输的设置以及外部扩展。切勿将密钥、私人故事和生成的状态放入公开的存储库中。
